## Non-Negotiable Invariants

1. **Continuous Doc API & OpenAPI Maintenance**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and OpenAPI 3.1 specification (`api/openapi/openapi.yaml`) MUST be kept updated on **every code change or addition**, regardless of how small the modification is, if any endpoint, schema, gRPC proto, cache key, or contract is touched.
2. **Secured Logging**: All logging must be structured JSON (`log/slog`). Strictly redact PII/PHI, client `Authorization` headers, bearer tokens, raw `caller_acl_bitmap` bytes, Redis/Triton credentials, and internal cluster paths/DSNs before emission.
3. **Native `uint32` Roaring Bitmap Entitlement Filtering**: Perform in-memory bitwise AND intersections between pre-fetched caller session Roaring Bitmaps and immutable `uint32 doc_id` candidates in sub-millisecond time with zero runtime UUID-to-integer translation overhead and zero heap allocations.
4. **Fixed Staged Candidate Cascade**: Enforce the deterministic narrowing cascade (`Top-40 Dense + Top-40 Sparse -> Top-20 RRF (k=60) -> Roaring Bitmap ACL Filter -> Top-10 Triton Cross-Encoder -> Top-5 Hydrated Parent Chunks`). Dynamic knee pruning and synchronous HyDE LLM expansion loops on the critical path are strictly prohibited.
5. **Deterministic Circuit Breaking**: If Triton Cross-Encoder logits drop below threshold $\tau$, P99 latency exceeds $35\text{ ms}$, or error rate exceeds $5\%$, trip the circuit breaker and promote top un-reranked RRF candidates directly.
6. **Normalized Text Query Caching**: Compute Tier 1 cache keys as `SHA256(Normalize(QueryText) + TenantID + EmbeddingModelVersion)` in Redis 7.2 Cluster, followed by mandatory Tier 2 live Roaring Bitmap entitlement verification before returning cached results ($\le 8\text{ ms}$ P99).
7. **Focused Retrieval Boundary**: Return structured, enriched parent chunks (800–1,500 tokens) over Protobuf v3 / REST. Prompt chat dialect compilation (Anthropic XML, Llama-3 headers) is strictly out of scope.
8. **Zero-Alloc Telemetry & Memory Discipline**: Use `sync.Pool` reusable candidate buffers and a lock-free ring buffer to emit compliance trace spans to `rag-telemetry-audit-daemon`. Configure `GOMEMLIMIT=3600MiB` and `GOGC=100` within 2 GiB request / 4 GiB limit pods.
9. **Code Cleanliness & Quality Gates**: All Go code must pass `gofmt -s`, `go vet`, `golangci-lint`, `govulncheck`, `gosec`, and `-race` test suites.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Go formatting: `gofmt -s -w .`.
2. Run Go static analysis: `go vet ./...` and `golangci-lint run`.
3. Run test suites: `go test -v -race ./...`.
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` are updated with all API, schema, proto, or cache contract modifications.
5. Verify Secured Logging rules: Ensure no bearer tokens, auth headers, raw `caller_acl_bitmap` bytes, credentials, or PII are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
